# Agent / LLM 工程师面试全景：考什么、怎么准备

:::观点 LLM 工程师面试和传统后端面试的本质区别
传统后端面试考的是"你懂不懂这个系统"；LLM 工程师面试考的是"你能不能在不确定性中做出正确的工程决策"。模型是黑盒，效果有随机性，很多问题没有标准答案——面试官真正在考察的是**你的判断框架和踩坑经验**，而不是背诵定义。
:::

---

## 一、考察维度全景

不同公司侧重不同，但基本围绕四个维度：

```
┌─────────────────────────────────────────────────┐
│  算法基础        LLM 专项        系统设计         行为面试  │
│  20%             30%             35%              15%    │
└─────────────────────────────────────────────────┘
```

**大厂（字节 / 阿里 / 百度 / 腾讯）**：算法基础比重更高，LeetCode Hard 仍是门槛，系统设计侧重规模化。

**AI 创业公司（Moonshot / MiniMax / 百川 / 智谱）**：几乎不考 LeetCode，重点考 LLM 专项和系统设计，更看重你做过什么、踩过什么坑。

**外企 AI 岗（Anthropic / OpenAI / Google DeepMind）**：代码质量要求极高，系统设计侧重 ML 系统，行为面试用 STAR 框架深挖影响力。

---

## 二、算法基础：够用就行，别投入太多

:::方法 LLM 岗的算法备战优先级
只准备高频、LLM 场景相关的题型，性价比最高：

**必须会（1–2 周刷完）**
- 数组 / 滑动窗口：Tokenization 相关处理
- 字符串操作：Prompt 解析、模板渲染
- 哈希表 / 计数：Token 频率统计
- 二分查找：Beam Search 的变体理解

**了解即可**
- 树 / 图：Multi-Agent 任务依赖图
- 动态规划：序列标注、路径规划

**可以不准备**
- 位运算、数学题（除非 JD 明确要求）

目标：LeetCode Medium 稳定通过，Easy 10 分钟内。不用刷到 Hard，时间用来深挖 LLM 专项更值。
:::

## 三、LLM 专项：真正的差异化竞争力

这是 LLM 岗独有的考察维度，也是大多数候选人准备最不充分的地方。

### 3.1 原理类高频题

| 考题 | 考察核心 | 答题要点 |
|---|---|---|
| Transformer 为什么用 Self-Attention 而不是 RNN？ | 架构理解 | 并行化 + 长距离依赖 + 梯度流 |
| KV Cache 是什么？为什么能加速推理？ | 推理优化 | 避免重复计算已生成 token 的 K/V |
| RLHF 的三个阶段分别做什么？ | 后训练 | SFT → RM 训练 → PPO 优化 |
| RAG 和 Fine-tune 怎么选？ | 工程判断 | 知识动态性 / 幻觉容忍度 / 成本 |
| Temperature / Top-p / Top-k 有什么区别？ | 解码策略 | 各自控制的分布变换方式 |

:::方法 原理题答题框架：是什么 → 为什么 → 怎么用
别只背定义。面试官追问"为什么这么设计"时，要能从**工程约束**出发推导出这个设计的必然性。比如 KV Cache：因为自回归解码每次只生成一个 token，已经计算过的历史 K/V 重复计算是纯浪费——这是工程约束，不是拍脑袋的设计。
:::

### 3.2 工程实践类高频题

这类题没有标准答案，考的是你的判断和踩坑经验：

**RAG 系统效果不好，你怎么排查？**

:::方法 RAG 排查的系统性思路
```
效果差
├─ 先看检索：Retrieved chunks 对不对？
│   → 错：切分策略、embedding 模型、索引问题
│   → 对但排序差：加 Reranker
├─ 再看生成：给了对的 chunks，答案还是错？
│   → 幻觉：prompt 限制不够严，加 faithfulness check
│   → 格式/完整性差：调整 prompt 结构
└─ 最后看评估：评估指标对不对？
    → 指标不对比什么都白搭
```
:::

**Prompt 效果不稳定，你怎么处理？**

核心答题思路：版本化 → 建黄金集 → 定量对比，不要靠感觉手调。（详见本系列「Chatbot 落地实战」）

**你们的 Agent 在生产上遇到过什么问题？**

:::提醒 这道题是在考你有没有真正上过生产
背书式回答会被立刻识破。准备 1–2 个真实的"我们遇到了 X 问题，根因是 Y，最终用 Z 方案解决"的故事，细节越具体越好（具体的指标、具体的排查过程）。
:::

## 四、系统设计：AI 岗最拉开差距的环节

### 4.1 常见题型

- 设计一个企业内部知识库问答系统（RAG 系统设计）
- 设计一个 AI 客服系统（Chatbot 系统设计）
- 设计一个 Code Assistant（工具调用 + 上下文管理）
- 设计一个 Multi-Agent 任务编排系统

### 4.2 答题框架

:::方法 AI 系统设计的回答结构（30 分钟版）
**前 5 分钟：澄清需求**
- 规模：QPS 多少？用户量？知识库大小？
- 质量要求：允许多高错误率？延迟上限？
- 约束：成本预算？必须用哪个模型？

**中间 15 分钟：核心架构**
- 画出主链路（用户 → 系统各模块 → 响应）
- 逐模块解释选型理由（为什么用这个，不用那个）
- 主动说出每个模块的 trade-off

**后 10 分钟：深挖两个难点**
- 主动选你最熟的两个点深入（别等面试官追问）
- 典型难点：幻觉控制、冷启动、延迟优化、成本控制
:::

:::观点 系统设计不是炫技，是展示判断力
面试官不期望你给出一个"完美方案"——完美方案不存在。他们在看：你能不能识别出关键约束，在多个合理方案之间做出有据可依的选择，并且清楚地说出你放弃了什么。说"我选 A 而不是 B，是因为在这个场景下 X 比 Y 更重要"，比说"我用最先进的 C 方案"有说服力得多。
:::

### 4.3 容易被忽视的加分项

- **评测方案**：你怎么知道系统效果好不好？（黄金数据集 + 指标体系）
- **降级策略**：模型挂了 / 超时了怎么办？
- **冷启动**：知识库为空时怎么处理第一批用户？
- **成本拆解**：大概多少钱一次查询，如何优化？

## 五、行为面试：被低估的一关

大厂行为面试用 **STAR 框架**（Situation / Task / Action / Result），AI 创业公司更随意但更在乎影响力。

:::方法 针对 LLM 岗的 STAR 故事准备清单
提前准备这几类故事，每类 1–2 个，面试前反复讲到流畅：

- **从 0 到 1 搭建了什么系统**：重点说架构决策和你的判断
- **遇到技术难题怎么解决**：重点说排查思路，不是结论
- **和产品 / 业务方有分歧怎么处理**：重点说你如何用数据说话
- **做了一个失败的决策**：重点说你从中学到了什么（真诚 > 完美）
- **推动了一个跨团队的改变**：重点说影响力和方法
:::

## 六、备战路径建议

```
第 1–2 周：补齐算法短板
  LeetCode 高频 100 题（数组 / 字符串 / 哈希），每天 2 题

第 3–4 周：系统梳理 LLM 专项
  读完本系列技术文章（Transformer → RAG → Agent 编排 → Harness）
  每篇文章整理成 3–5 句话的口答版

第 5–6 周：系统设计专项训练
  每天一道系统设计题，自己先独立作答，再对照本系列文章补充细节
  找 1–2 个朋友做 Mock Interview

第 7 周：行为面试
  写出 5 个 STAR 故事，录音回听，磨到流畅自然

第 8 周：模拟面试 + 查漏补缺
  全流程 Mock，找真实在做 LLM 的朋友帮你压场
```
